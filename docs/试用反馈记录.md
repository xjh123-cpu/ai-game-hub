## 一、反馈收集方式

| 方式 | 说明 |
|------|------|
| 公开链接试用 | 把链接发给同学/朋友，任意设备打开即可游玩（Streamlit 免费版需先用 Google / GitHub 账号登录） |
| 即时通讯/口头反馈 | 使用过程中遇到问题直接反馈（含截图） |
| 提问清单引导 | 按下表逐项询问，避免只得到「挺好玩的」这类无法行动的反馈 |

### 提问清单（照着问就能拿到有效反馈）

1. 从打开链接到看见第一句剧情，大概等了多久？中间有没有以为「卡死了」？
2. 猜谜模式出的题，有没有你一眼就看到答案的？或者答案本身是错的？
3. 文字冒险里你试过输入奇怪的内容吗（比如让它泄露规则）？它怎么反应的？
4. 有没有哪一步点了按钮但页面没反应？
5. 积分、进度有没有莫名消失过？
6. 你还会想再玩第二次吗？为什么？

## 三、反馈驱动的迭代闭环（答辩可讲的故事）

F-01 是最有价值的一条——它走通了「真实用户反馈 → 根因定位 → 双层修复 → 验证上线」的完整链路：

1. **反馈**：玩家截图反馈谜面写着「名字叫蝙蝠」，等于把答案直接送给玩家。
2. **根因定位**（两层，缺一不可）：
   - *提示词层*：出题模板只要求「谜面有趣」，没有禁止出现谜底字词，temperature=1.0 时模型走了捷径；
   - *代码层*：出题结果只校验字段是否齐全，不校验内容是否泄露。
3. **修复**：
   - `prompts.py`：出题模板新增最高优先级规则——谜面与提示中绝不能出现谜底本身或其字词，只能间接描述；
   - `games/quiz.py`：新增 `answer_leaked()` 泄露检测，命中后把原因反馈给模型自动重新出题（与事实核查共用重试通道）。
4. **验证**：把该缺陷固化为回归用例 **T13**（见 `tests/test_cases.py`），保证后续任何改动都不会让问题复活。

这正是实验 5-5「评估与迭代」要考察的东西：**不是「我试了试效果不错」，而是「发现了什么、为什么发生、怎么修、怎么保证不再犯」。**
